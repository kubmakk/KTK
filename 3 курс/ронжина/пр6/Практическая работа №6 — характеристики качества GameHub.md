# Практическая работа №6

## Измерение и анализ эксплуатационных характеристик качества GameHub

Цель работы — измерить эксплуатационные характеристики платформы GameHub, сравнить фактические значения с критериями технического задания, определить причины отклонений и разработать план улучшений.

Объект измерений — ИС GameHub версии `1.0.0`. Проверка выполнена на продуктивном стенде, повторяющем рабочую конфигурацию: три экземпляра API, PostgreSQL с репликой, Redis-кеш, CDN, клиент Windows 11 и канал 1 Гбит/с. Для измерений использованы обезличенные тестовые данные каталога из 50 000 игр.

## Задание 1. Формирование перечня характеристик

| № | Характеристика | Показатель | Единица | Критерий |
|---:|---|---|---|---|
| 1 | Производительность | Среднее время ответа API при 5 000 RPS | мс | Не более 150 мс |
| 2 | Производительность поиска | Время поиска по каталогу из 50 000 игр | мс | Не более 200 мс |
| 3 | Удобство и производительность клиента | Время от запуска клиента до готовности главного окна | с | Не более 5 с |
| 4 | Надёжность операций | Доля успешных запросов при нагрузке | % | Не менее 99,95% |
| 5 | Восстанавливаемость | Время восстановления после инцидента P1 | мин | Не более 45 мин |

Ожидаемый результат — все пять показателей соответствуют установленным критериям, а единичные выбросы имеют объяснимую причину и не создают риск для целевых сценариев.

## Задание 2. Планирование измерений

| Показатель | Условия | Метод | Замеры | Норма |
|---|---|---|---:|---|
| Время ответа API | 100 000 активных сессий, 5 000 RPS, прогрев 10 мин | Нагрузочный профиль из практической работы №3, метрики API Gateway | 3 запуска по 20 мин | ≤ 150 мс в среднем |
| Время поиска | Каталог 50 000 игр, кеш очищается перед первым циклом | 100 запросов в каждом цикле, фиксация среднего и максимума | 3 серии | ≤ 200 мс |
| Время запуска клиента | Windows 11, NVMe SSD, очищенный пользовательский кеш | От запуска процесса до доступности каталога | 3 запуска | ≤ 5 с |
| Успешные запросы | Смешанный профиль каталога, авторизации, библиотеки и оплаты | Отношение HTTP 2xx/3xx к общему числу корректных запросов | 3 серии | ≥ 99,95% |
| Время восстановления P1 | Имитация недоступности активного API-контура | От сигнала мониторинга до успешного smoke-теста после переключения | 3 учебных инцидента | ≤ 45 мин |

Последовательность действий:

1. Зафиксировать версию ПО, конфигурацию стенда и состояние мониторинга.
2. Выполнить smoke-тест до начала измерений.
3. Провести три независимых замера каждого показателя.
4. Сохранить метрики, логи и время начала и окончания каждого цикла.
5. Рассчитать среднее значение и сравнить его с нормой.
6. Для любого отклонения определить возможные причины и проверить их отдельно.
7. После улучшений повторить измерения в тех же условиях.

- Клиент до показа главного окна синхронно загружал манифест новостей и проверял локальную библиотеку.
- Во второй нагрузочной серии ошибки были связаны с кратковременными ответами `503` тестового платёжного шлюза.
- Во втором учебном инциденте дежурный инженер потратил 19 минут на ручное определение активного контура и проверку реплики базы данных.

## Задание 4. Анализ отклонений

| 2 | Блокирующая синхронизация библиотеки при запуске клиента | Отключить синхронизацию и сравнить трассировки запуска | Без синхронизации главное окно готово за 3,9 с |

Ключевыми причинами отклонений признаны блокирующая инициализация клиента и недостаточная автоматизация аварийного переключения. Аппаратных ограничений и перегрузки базы данных не выявлено.

## Задание 6. Итоговый отчёт

### Выполненные действия

1. Выбраны пять эксплуатационных характеристик GameHub и установлены измеримые критерии.
2. Составлен план из трёх независимых замеров каждого показателя.
3. Проведена учебная серия измерений в условиях целевой нагрузки.
4. Выявлены четыре отклонения, определены и проверены их причины.
5. Реализован план улучшений и выполнена контрольная серия.

### Итоговые результаты

До улучшений полностью соответствовал норме один показатель, два соответствовали по среднему значению, но имели единичные отклонения, и два не соответствовали требованиям. После оптимизации все пять показателей соответствуют установленным критериям во всех трёх контрольных замерах.

### Рекомендации для эксплуатации

- хранить историю метрик не менее 90 дней и отслеживать тенденции, а не только отдельные значения;
- выполнять прогрев кешей после каждого обновления поискового индекса;
- проверять время запуска клиента на эталонном и минимально допустимом оборудовании;
- проводить квартальные учения по восстановлению после P1;
- менять порог допуска релиза только через согласованное изменение ТЗ или эксплуатационного регламента;
- оформлять каждое превышение нормы отдельной записью в журнале проблем.

## Вывод

В ходе практической работы измерены производительность, надёжность, удобство и восстанавливаемость GameHub. Первичная проверка выявила медленный запуск клиента, отдельные задержки поиска, недостаточную устойчивость к временным ошибкам платёжного шлюза и превышение времени восстановления. После фоновой инициализации клиента, прогрева кеша, введения безопасных повторов и автоматизации аварийного переключения все показатели достигли нормы. Система может эксплуатироваться при условии постоянного мониторинга SLO и регулярной контрольной проверки.
