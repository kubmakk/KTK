# Пояснение к практической работе 2

## Что делает программа

Программа хранит заметки в элементе `ListBox` на первой форме. Пользователь вводит текст в `TextBox`, добавляет его в список, удаляет выбранную строку, сортирует список и сохраняет его в текстовый файл. По кнопке открывается вторая форма, куда передаётся копия текущего списка. На второй форме каждая заметка отображается в `CheckedListBox`, поэтому рядом с ней можно поставить галочку.

В проекте ровно две формы: `Form1` и `Form2`.

## Из каких файлов состоит проект

| Файл | Для чего нужен |
|---|---|
| `Практическая2_СписокЗадач.csproj` | Настройки проекта: WinForms, .NET 8, имя сборки. |
| `Program.cs` | Точка входа. Создаёт и запускает `Form1`. |
| `Form1.Designer.cs` | Создаёт элементы первой формы, задаёт их размеры, подписи и связывает события с методами. |
| `Form1.cs` | Содержит логику добавления, удаления, сортировки, сохранения и открытия второй формы. |
| `Form2.Designer.cs` | Описывает внешний вид второй формы. |
| `Form2.cs` | Получает заметки, помещает их в список с галочками и закрывает форму по кнопке «Назад». |

`Form1.cs` и `Form1.Designer.cs` описывают один класс благодаря слову `partial`. Visual Studio разделяет форму на две части: в одной удобно держать нашу логику, в другой — автоматически создаваемый код интерфейса.

## Как начинается выполнение

В `Program.cs` находится метод `Main`:

```csharp
ApplicationConfiguration.Initialize();
Application.Run(new Form1());
```

Первая строка включает стандартные настройки современного WinForms-приложения. Вторая создаёт объект первой формы и запускает цикл обработки событий. Пока `Form1` открыта, приложение работает.

Атрибут `[STAThread]` нужен для Windows-компонентов интерфейса, диалогов выбора файла и буфера обмена. Для обычного WinForms-проекта его оставляют у метода `Main`.

## Элементы первой формы

Вместо бессмысленных имён наподобие `button1` используются осмысленные имена:

| Имя | Тип | Назначение |
|---|---|---|
| `txtNote` | `TextBox` | Ввод новой заметки. |
| `lstNotes` | `ListBox` | Хранение и показ заметок. |
| `btnAdd` | `Button` | Добавление текста из `txtNote`. |
| `btnDelete` | `Button` | Удаление выбранной строки. |
| `btnSort` | `Button` | Сортировка по алфавиту. |
| `btnSave` | `Button` | Сохранение в файл `.txt`. |
| `btnOpenSecondForm` | `Button` | Создание и показ `Form2`. |

Имена помогают читать выражения вроде `lstNotes.Items.Add(note)`: сразу видно, что строка добавляется в список заметок.

## Что такое событие

WinForms работает по событиям. Пользователь нажал кнопку — возникло событие `Click`; нажал клавишу — событие `KeyDown`. В `Designer` событие связывается с методом:

```csharp
btnAdd.Click += btnAdd_Click;
txtNote.KeyDown += txtNote_KeyDown;
```

Метод, который вызывается при событии, называется обработчиком. Параметр `sender` содержит объект, вызвавший событие, а `e` — дополнительные данные события. Например, у `KeyEventArgs e` можно узнать нажатую клавишу через `e.KeyCode`.

## Добавление заметки

И кнопка, и клавиша `Enter` вызывают один метод `AddNote`. Это сделано, чтобы не копировать одинаковый код в разные обработчики.

```csharp
string note = txtNote.Text.Trim();
```

`Text` берёт введённую строку. `Trim()` убирает пробелы в начале и конце. Затем `string.IsNullOrWhiteSpace(note)` проверяет, не является ли строка пустой. Пустая заметка не добавляется, а пользователь видит `MessageBox`.

Добавление выполняет строка:

```csharp
lstNotes.Items.Add(note);
```

`Items` — коллекция строк внутри `ListBox`. После добавления поле очищается методом `Clear()`, а `Focus()` возвращает в него курсор.

В обработчике `Enter` установлено `e.SuppressKeyPress = true`. Это не даёт Windows дополнительно подать звуковой сигнал после обработки клавиши.

## Удаление заметки

`lstNotes.SelectedIndex` содержит номер выбранной строки. Если ничего не выбрано, значение равно `-1`.

```csharp
if (lstNotes.SelectedIndex < 0)
```

Поэтому сначала выполняется проверка, а затем выбранный элемент удаляется:

```csharp
lstNotes.Items.RemoveAt(selectedIndex);
```

Кнопка «Удалить» и клавиша `Delete` вызывают общий метод `DeleteSelectedNote`, поэтому их поведение одинаково.

## Сортировка

Элементы `ListBox` хранятся как `object`, поэтому перед сортировкой они преобразуются в строки:

```csharp
string[] sortedNotes = lstNotes.Items
    .Cast<object>()
    .Select(item => item.ToString() ?? string.Empty)
    .OrderBy(note => note, StringComparer.CurrentCultureIgnoreCase)
    .ToArray();
```

- `Cast<object>()` позволяет использовать LINQ для коллекции элементов;
- `Select(...)` получает текст каждого элемента;
- `OrderBy(...)` сортирует строки;
- `CurrentCultureIgnoreCase` учитывает правила текущего языка и не разделяет буквы по регистру;
- `ToArray()` создаёт готовый массив.

После этого старое содержимое очищается, а отсортированный массив добавляется обратно. `BeginUpdate()` и `EndUpdate()` предотвращают мерцание списка во время замены элементов.

## Сохранение в текстовый файл

`SaveFileDialog` показывает стандартное окно выбора места и имени файла. Если пользователь нажал «Отмена», метод сразу завершается.

```csharp
File.WriteAllLines(dialog.FileName, notes, Encoding.UTF8);
```

`File.WriteAllLines` создаёт файл и записывает каждый элемент массива на отдельной строке. `Encoding.UTF8` нужна для правильного сохранения русских букв.

Операция находится внутри `try/catch`. Ошибки работы с файлами возможны, например, если нет прав на папку или файл занят. В `catch` вместо аварийного завершения показывается понятное сообщение.

## Передача данных на вторую форму

Сначала содержимое `ListBox` копируется в массив `string[]`. Затем массив передаётся в конструктор второй формы:

```csharp
using Form2 secondForm = new(notes);
secondForm.ShowDialog(this);
```

Конструктор `Form2(IEnumerable<string> notes)` принимает любую последовательность строк. Цикл `foreach` добавляет каждую строку в `CheckedListBox`:

```csharp
checkedNotes.Items.Add(note, false);
```

Второй аргумент `false` означает, что новая строка изначально не отмечена.

`ShowDialog(this)` открывает форму в модальном режиме: сначала нужно закрыть `Form2`, а затем продолжать работу с `Form1`. Конструкция `using` гарантирует освобождение ресурсов формы после закрытия.

## Почему галочки не возвращаются на первую форму

По заданию требуется перенести заметки на вторую форму и дать возможность отметить их. Возврат состояния галочек не требуется, поэтому `Form2` получает копию строк только для отображения. Сами заметки на первой форме не изменяются.

## Как рассказать код преподавателю

Короткое объяснение может звучать так:

> В `Program.cs` запускается `Form1`. Интерфейс формы описан в `Designer`, а обработчики событий находятся в `Form1.cs`. Заметки хранятся в коллекции `Items` элемента `ListBox`. Кнопка и Enter вызывают общий метод добавления, кнопка и Delete — общий метод удаления. Перед сортировкой элементы превращаются в массив строк и сортируются через LINQ. Для сохранения используется `SaveFileDialog` и `File.WriteAllLines`. При открытии `Form2` массив заметок передаётся в её конструктор и заполняет `CheckedListBox`.

## Проверка перед показом

- Пустая строка не добавляется.
- `Enter` добавляет заметку.
- `Delete` удаляет выбранную заметку.
- Сортировка работает независимо от регистра букв.
- В сохранённом файле каждая заметка находится на отдельной строке.
- На второй форме видны все текущие заметки и ставятся галочки.
- Кнопка «Назад» закрывает вторую форму и возвращает к первой.
