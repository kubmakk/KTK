# Пояснение к практической работе 3

## Что делает программа

Первая форма проверяет логин и пароль. После успешного входа она прячется и открывает вторую форму — каталог книг. Набор видимых элементов второй формы зависит от роли пользователя:

| Число | Роль | Что видно |
|---:|---|---|
| `0` | гость | список книг и выход |
| `1` | пользователь | список книг и выход |
| `2` | модератор | список, сортировка и выход |
| `3` | администратор | список, сортировка, ввод, добавление, удаление и выход |

Недоступные элементы получают `Visible = false`, поэтому они именно скрыты, как требует задание.

## Из каких файлов состоит проект

| Файл | Для чего нужен |
|---|---|
| `Практическая3_КаталогКниг.csproj` | Настройки WinForms-проекта для .NET 8. |
| `Program.cs` | Запускает окно авторизации `Form1`. |
| `Form1.Designer.cs` | Создаёт поля логина и пароля, флажок и кнопки входа. |
| `Form1.cs` | Проверяет учётные данные и передаёт имя и роль на вторую форму. |
| `Form2.Designer.cs` | Создаёт список книг, подпись пользователя и кнопки действий. |
| `Form2.cs` | Заполняет каталог, настраивает права и выполняет действия с книгами. |

В проекте ровно две формы — `Form1` и `Form2`.

## Учётные данные

| Роль | Логин | Пароль |
|---|---|---|
| Пользователь | `user` | `user123` |
| Модератор | `moderator` | `mod123` |
| Администратор | `admin` | `admin123` |

Для гостя есть отдельная кнопка, логин и пароль не нужны.

## Почему роль хранится в `int`

Задание требует обычное целое число. После проверки логина переменная `role` получает `1`, `2` или `3`, а при гостевом входе — `0`.

```csharp
int role;

if (login == "user" && password == "user123")
{
    role = 1;
}
```

В проекте числа вынесены в константы `UserRole`, `ModeratorRole` и `AdministratorRole`. Константа всё равно имеет тип `int`, но имя делает код понятнее и помогает не перепутать значения.

## Почему логины проверяются через `if`

По условию логины и пароли должны находиться прямо в коде в виде условий. Поэтому база данных и отдельный файл пользователей не применяются.

Оператор `&&` означает «и»: условие истинно, только если одновременно совпадают логин и пароль. Ветка `else` выполняется, если не подошла ни одна пара. Там показывается сообщение об ошибке и выполнение обработчика прекращается с помощью `return`.

Хранить настоящие пароли прямо в коде небезопасно. Здесь это сделано только потому, что так сформулировано учебное задание.

## Поле пароля и флажок показа

В `Designer` у поля задано:

```csharp
txtPassword.PasswordChar = '*';
```

Поэтому вместо символов пароля видны звёздочки. Обработчик флажка меняет символ маски:

```csharp
txtPassword.PasswordChar = chkShowPassword.Checked ? '\0' : '*';
```

Это тернарный оператор. Если флажок установлен, используется `\0`, то есть маска отключается. Иначе снова используется `*`.

## Переход между формами

После успешной авторизации вызывается:

```csharp
OpenWorkspace(login, role);
```

Метод сначала выполняет `Hide()`, чтобы спрятать окно входа. Затем создаёт вторую форму и передаёт ей имя пользователя и целое число роли:

```csharp
using Form2 workspace = new(userName, role);
workspace.ShowDialog();
```

Когда пользователь нажимает «Выйти», `Form2` закрывается. Выполнение `OpenWorkspace` продолжается: пароль очищается, первая форма снова показывается методом `Show()`.

Это важно: `Form1` не уничтожается, а временно скрывается. Поэтому после выхода не нужно запускать новое приложение.

## Откуда берётся подпись с пользователем

Конструктор второй формы получает `userName` и `role`. Метод `GetRoleName` переводит число роли в понятный текст:

```csharp
lblCurrentUser.Text = $"Вы вошли как: {userName} ({GetRoleName(role)})";
```

Символ `$` перед строкой включает интерполяцию — значения внутри фигурных скобок подставляются в текст.

`GetRoleName` использует выражение `switch`: для `1` возвращается «пользователь», для `2` — «модератор», для `3` — «администратор», а для остальных значений — «гость».

## Как заполняется каталог

Темой выбрана библиотека книг. Она отличается от показанного в задании примера магазина. Начальные строки добавляются методом `AddRange`:

```csharp
lstBooks.Items.AddRange(
[
    "Мастер и Маргарита — Михаил Булгаков",
    "Преступление и наказание — Фёдор Достоевский"
]);
```

`Items` — коллекция элементов `ListBox`, а `AddRange` добавляет сразу несколько записей.

## Как скрываются действия по ролям

Главная часть разграничения доступа находится в `ConfigureRoleAccess`:

```csharp
bool canSort = currentRole >= ModeratorRole;
bool isAdministrator = currentRole == AdministratorRole;

btnSort.Visible = canSort;

lblNewBook.Visible = isAdministrator;
txtNewBook.Visible = isAdministrator;
btnAdd.Visible = isAdministrator;
btnDelete.Visible = isAdministrator;
```

Модератор имеет роль `2`, администратор — `3`, поэтому условие `>= 2` разрешает сортировку обоим. Добавление и удаление появляются только при точном равенстве роли значению `3`.

Используется свойство `Visible`, а не `Enabled`. При `Enabled = false` кнопка оставалась бы на форме серой. При `Visible = false` она вообще не отображается, что соответствует условию задания.

## Сортировка каталога

Коллекция элементов преобразуется в строки и сортируется через LINQ:

```csharp
.OrderBy(book => book, StringComparer.CurrentCultureIgnoreCase)
```

`OrderBy` располагает названия по алфавиту. `CurrentCultureIgnoreCase` использует правила текущей культуры Windows и не считает регистр букв причиной для другого порядка.

Кнопка сортировки доступна модератору и администратору.

## Добавление книги

Текст берётся из `txtNewBook`, а `Trim()` удаляет лишние пробелы по краям. Пустые строки не добавляются. Правильная строка попадает в список:

```csharp
lstBooks.Items.Add(newBook);
```

После этого поле очищается, а курсор возвращается в него. Поле и кнопка видимы только администратору.

## Удаление книги

`SelectedIndex` содержит индекс выбранной книги. Значение `-1` означает, что выбор отсутствует. Программа сначала проверяет это и показывает сообщение, если удалять нечего. Иначе выполняется:

```csharp
lstBooks.Items.RemoveAt(lstBooks.SelectedIndex);
```

Кнопка удаления тоже видна только администратору.

## Что означают `namespace`, `class` и конструктор

- `namespace Practice3BookCatalog` объединяет классы проекта и защищает их имена от совпадений с классами других проектов.
- `class Form1 : Form` создаёт класс `Form1`, унаследованный от стандартного окна WinForms `Form`.
- `public Form1()` — конструктор. Он выполняется при создании формы.
- `InitializeComponent()` создаёт элементы, которые описаны в соответствующем `Designer`-файле.
- `private` означает, что поле или метод используется только внутри этого класса.
- `readonly` у `currentRole` означает, что роль задаётся в конструкторе и потом случайно не меняется.

## Что такое обработчики кнопок

В `Designer` кнопки связываются с методами:

```csharp
btnLogin.Click += btnLogin_Click;
btnLogout.Click += btnLogout_Click;
```

Когда происходит `Click`, WinForms сам вызывает нужный метод. Поэтому в обычной программе не нужно постоянно проверять, нажал ли пользователь кнопку: приложение ждёт события.

## Как рассказать код преподавателю

Короткое объяснение может звучать так:

> Программа запускает `Form1`. Логин и пароль проверяются цепочкой `if`, как указано в задании, а роль хранится в `int`: от 0 до 3. При успешном входе `Form1` скрывается, а имя и роль передаются в конструктор `Form2`. Вторая форма заполняет `ListBox` каталогом книг и методом `ConfigureRoleAccess` меняет свойство `Visible` у элементов. Модератор и администратор видят сортировку, а ввод, добавление и удаление видит только администратор. После кнопки «Выйти» вторая форма закрывается, а первая снова показывается.

## Проверка перед показом

- Неверные данные показывают `MessageBox`.
- Флажок показывает и снова скрывает пароль.
- Гость и пользователь не видят кнопок действий и поле ввода.
- Модератор видит только дополнительную сортировку.
- Администратор видит сортировку, ввод, добавление и удаление.
- Недоступные элементы отсутствуют на форме, а не отображаются отключёнными.
- После выхода снова открывается форма авторизации.
